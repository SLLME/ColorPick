# 拍照取色小程序

从照片中精确提取颜色的微信小程序。拍照或选图后，点击取色、长按拖动放大镜精调，支持多色彩空间、配色推荐与色卡收藏。

## 快速开始

1. 打开**微信开发者工具** → 导入项目
2. 目录选择本文件夹 `E:/WeChatMini`
3. AppID 填自己的，或直接选「测试号」
4. 编译运行

> 真机预览需在 `project.config.json` 中填入自己的 AppID。拍照功能在**真机**上才能完整验证，开发者工具只能走相册/本地图片。

## 功能

### 取色页

| 功能 | 说明 |
| --- | --- |
| 拍照 / 相册 | `wx.chooseMedia`，单张上限 10MB，相机默认后置 |
| 点击取色 | 点图片任意位置即取该点颜色 |
| 取样范围 | 精确 1×1 / 标准 5×5 / 平滑 11×11 三档，取区域平均可显著减少噪点影响；选择会被记住 |
| 长按放大镜 | 长按 180ms 进入精调模式，8 倍放大镜跟随触点，拖动实时取色 |
| 当前颜色 | 大色块 + HEX + RGB + HSL + HSV + CMYK，可一键复制 |
| 对比度检查 | 该色当背景时配白字 / 深色字的 WCAG 对比度与等级，并给出推荐文字色 |
| 色值格式 | 5 种格式逐项复制到剪贴板 |
| 配色方案 | 互补 / 分裂互补 / 邻近 / 三角 / 四方 / 同色明暗，共 6 组。点色块即选中该色**并复制色值** |
| 图片主色 | 自动分析整图主色及占比。点色块即选中该色**并复制色值** |
| 存入色卡 | 一键收藏当前颜色 |

### 色卡页

- 网格展示所有收藏颜色，背景带色值
- 点色卡看详情：改名字、复制任意格式、查看该色的 6 组配色
- 从配色里点色块可直接加入色卡
- 导出全部色值（HEX / RGB / HSL，制表符分隔，可直接粘进表格）
- 单个删除 / 全部清空，均有二次确认

## 实现要点

**取色原理**：用 `wx.getImageInfo` 获取图片原始宽高与拍摄方向，再把图片绘到 `type="2d"` 的 canvas 上（后备缓冲按 `devicePixelRatio` 放大以保证精度），最后用 `ctx.getImageData()` 读取像素并求平均。

**⚠️ 不要用 `wx.createImage`**：它是**小游戏**专属 API，小程序基础库中不存在，调用会抛 `TypeError: wx.createImg is not a function`，导致流程中断、loading 卡死。小程序里获取图片信息用 `wx.getImageInfo`，加载绘制源用 canvas 节点的 `createImage()`。

**Exif 方向**：手机竖拍照片带旋转标记，`wx.getImageInfo` 返回的 `width`/`height` 是**旋转前**的尺寸。必须按 `orientation` 交换宽高并施加对应变换（支持全部 8 种方向），否则方向错误、宽高比也算错。

## 取样范围与对比度

### 取样范围

单像素取色在照片上很脆弱：噪点和 JPEG 压缩伪影会让相邻两次点同一位置得到不同色值。所以默认取一小块区域求平均。三档预设写在 `index.js` 顶部的 `SAMPLE_PRESETS`：

| 档位 | 边长（显示像素） | 适用场景 |
| --- | --- | --- |
| 精确 | 1×1 | 细小色块、边缘分明的图标 |
| 标准 | 5×5 | 默认档，多数照片 |
| 平滑 | 11×11 | 噪点明显、需要稳定色值的场景 |

选择结果存在 `wx.setStorageSync('picker_sample_size')`，下次进入自动恢复；存储值非法时回落到默认档。

**坐标约定**：选点落在**显示像素** `floor(x), floor(y)` 上，以这一个显示像素为中心取 `sampleSize × sampleSize` 个显示像素。

不要写成「把选点当几何中心」——那样在 `dpr > 1` 时会有半像素偏移，`dpr = 3` 时「精确」档会横跨两个显示像素、取到两像素的混色。按显示像素对齐后，`size = 1` 恰好是那一个显示像素（`dpr × dpr` 个物理像素），任何 dpr 下都无歧义。

注意 `ctx.getImageData` 工作在**后备缓冲（物理像素）坐标系**，不受 `ctx.scale(dpr, dpr)` 影响，所以坐标要乘 `dpr`。

**视觉反馈**：图片上会画出与取样区域等大的方框，让「平均了多大一块」可见。此时**不再画圆环**——圆环直径是固定的，和取样方框尺寸对不上，两个大小不一致的图形叠在一起会让人误判取样范围。圆环只在单像素档出现（那时方框只有 1px，看不见）。

**区域均匀度**：顺带算区域亮度的标准差，给出定性提示（很均匀 / 基本均匀 / 有花纹或边缘）。离散度大说明拿到的是平均色而非某处的颜色，这个信号比单纯给个色值更能帮用户判断该不该信任结果。

### 对比度

回答「这个色能不能当底色、上面放什么字才看得清」。用 WCAG 2.x 公式 `(L_亮 + 0.05) / (L_暗 + 0.05)`，分级按 WCAG 2.1：

| 比值 | 等级 | 含义 |
| --- | --- | --- |
| ≥ 7 | AAA | 普通正文也达标 |
| ≥ 4.5 | AA | 普通正文达标 |
| ≥ 3 | 大字 AA | 仅大号文字（≥18pt 或 ≥14pt 粗体）达标 |
| < 3 | 不达标 | 不适合承载文字 |

**`readableTextColor` 的坑**：原先用固定亮度阈值 0.55 判断配白字还是深色字，这个阈值是错的。白色文字的对比度是 `1.05/(L+0.05)`，深色文字是 `(L+0.05)/0.05`，两者在 **L ≈ 0.179** 处才相等。阈值取 0.55 会让中间调背景（如 `#A9A9A9`，L ≈ 0.40）配白字，实际对比度只有 2.35:1，而深色文字可达 7.38:1。现在直接比较两种候选文字色的对比度取较大者——中灰、主题橙 `#FF5A3C` 等都因此改配了深色字。

## 页面布局（重要）

取色页在有图状态下**页面整体不滚动**，改成上下两块各管各的：

```
.page-fixed  height:100vh  overflow:hidden  flex-column
├─ .stage-wrap   高度 = 图片显示高度（由 JS 算出，上限为视口高度的 50%）
│   └─ .stage     尺寸恰好等于图片显示尺寸，居中
│        └─ canvas + 选点标记
├─ .hint-bar     重拍 / 换图
├─ .magnifier    position:fixed，必须在 scroll-view 之外
└─ .detail-scroll   flex:1  取色结果在这里独立滚动
```

这样做的三个原因，每一条都对应一个真实踩过的坑：

1. **图片区必须限高**。竖拍照片按原比例铺满宽度，高度会达到 667px 甚至更多，在 812px 视口里几乎占满整屏，下方色值被挤出去，用户很难滚到。现在按 `min(可用宽/图宽, 上限高/图高)` 等比缩放，整图完整可见，且高度不超过 `MAX_H_RATIO`（默认 0.5，在 `index.js` 顶部可调）。
2. **图片区和内容区不能抢手势**。canvas 上有 `disable-scroll="{{true}}"`（防止拖拽取色时页面跟着滚），如果页面本身还要靠滑动来滚，就会出现「只有从图片边缘才能滚动」的怪现象。把取色结果放进独立 `scroll-view` 后，两者互不干扰。
3. **放大镜不能放进 scroll-view**。`scroll-view` 内部可能使用 `transform`，会让 `position: fixed` 失效，放大镜会错位。

**顺带解决了坐标问题**：页面不滚动，舞台在视口中的位置就恒定，坐标换算不再依赖滚动时重测。

**canvas 尺寸的确定方式**：可用宽度取自**包裹层 `#stageWrap`**（宽度由 CSS 决定、与图片无关），不能用 canvas 自身的宽度——canvas 宽度由内联 `canvasStyle` 决定，而 `canvasStyle` 又要等尺寸算完才设置，读它会拿到 0，形成循环依赖。

**坐标换算**：`Touch` 对象**只有** `clientX/clientY`（相对视口）和 `pageX/pageY`（相对页面），**没有**相对元素的坐标（`x`/`y` 只存在于 Tap 类事件的 `detail` 里）。所以必须减去舞台在视口中的位置。放大镜用 `position: fixed`，同样基于视口坐标。

**loading 的幂等管理**：`wx.showLoading` / `wx.hideLoading` 需成对调用。统一走 `endLoading()` 做幂等关闭，并在所有异常路径（`getImageInfo` 失败、绘制源加载失败、canvas 重试耗尽、包裹层未布局）上都保证关闭。

**性能**：拖动取色走 40ms 节流；放大镜拖动时跳过配色方案重算（`silent` 模式），避免高频 setData 卡顿。

**主色提取**：颜色量化到 4bit/通道分桶，再合并视觉相近的桶。采样按**行列二维**跳采，避免一维步进与图片行宽产生共振而系统性漏采某一列。

**点击色块 = 选中 + 复制**：配色方案和图片主色这两处的色块，都是「看一眼就想拿去用」的场景，选色和复制基本同时发生，所以合成一步（`applyHex`）。要单独复制其它格式仍走「色值格式」列表。复制统一走 `copyText()`：`wx.setClipboardData` 自带的「内容已复制」提示会被换成带内容的提示，让用户明确知道复制到的是什么；**失败时也要给反馈**，否则用户会以为已经复制成功了。

## 已知限制

- 只支持单张取色，未做多图切换
- 主色提取为轻量量化算法，非 k-means，极端渐变图可能偏差
- 色卡存在 `wx.setStorageSync`，单 key 容量上限 10MB，实际可存数千色
